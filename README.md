# Stride

> **Move through your day with clarity.**
>
> A minimal, modern personal task manager built with Next.js 15. Stride helps
> you capture work, keep priorities visible, and stay focused on what matters
> next — without getting in your way.

## Highlights

- **Minimal core**: capture, prioritize, complete. No clutter.
- **Drag to reorder**: a grip handle on every card lets you arrange the list however you want — keyboard-accessible (`Tab` to grip, `Space` to lift, arrows to move, `Enter` to drop).
- **Status workflow**: `To do → In progress → Done`, accessible in one click.
- **Snappy UI**: optimistic updates with React 19 `useOptimistic`.
- **Fully responsive**: a thoughtful experience on phone, tablet, and desktop.
- **Light & dark modes** with system sync via `next-themes`.
- **Production-ready foundation**: server actions, typed validation, indexed
  SQLite store, and a clean module layout designed for open source.

## Quick start

> Requires **Node.js ≥ 20**.

```bash
# 1. Install dependencies
npm install

# 2. (Optional) configure environment
cp .env.example .env.local

# 3. Start the dev server
npm run dev
```

Open <http://localhost:3000>. The SQLite database is created automatically at
`./data/stride.db` on first request.

## Data model

Tasks are stored in a single indexed table:

| Column        | Type           | Notes                                  |
| ------------- | -------------- | -------------------------------------- |
| `id`          | `text PK`      | nanoid generated by the server action  |
| `title`       | `text`         | Required, ≤ 140 chars                  |
| `description` | `text?`        | Up to 2000 chars                       |
| `priority`    | `text`         | `low \| medium \| high \| urgent`      |
| `status`      | `text`         | `todo \| in_progress \| done`          |
| `due_date`    | `text?`        | ISO‑8601 string                        |
| `completed_at`| `text?`        | Set when status becomes `done`         |
| `position`    | `real`         | User-controlled order (drag to reorder)|
| `created_at`  | `text`         | ISO‑8601, defaulted by SQLite          |
| `updated_at`  | `text`         | ISO‑8601, written on every mutation    |

Indexes cover `status`, `priority`, `due_date`, `position`, and `created_at` so the
dashboard sort/filter operations stay cheap as the dataset grows.

The very first connection runs an idempotent
`CREATE TABLE IF NOT EXISTS …` bootstrap so the app works without manual
migration steps. When you start evolving the schema, switch to versioned
Drizzle migrations:

```bash
npm run db:generate     # creates src/lib/db/migrations/NNNN_*.sql
npm run db:migrate      # applies them
```

## Deployment notes

- **Self-hosted (recommended for a personal app)**: SQLite + a persistent
  volume works out of the box. Use a Node host (Fly, Railway, Render, your
  own server, Docker, etc.) and mount a volume at `./data`.
- **Vercel / serverless**: SQLite is unsuitable for ephemeral filesystems.
  Swap the `better-sqlite3` driver for one of:
  - **Postgres** (Neon, Supabase, RDS) using
    [`drizzle-orm/node-postgres`](https://orm.drizzle.team/docs/get-started-postgresql)
  - **libSQL/Turso** using
    [`drizzle-orm/libsql`](https://orm.drizzle.team/docs/get-started-sqlite#turso)

  The schema in `src/lib/db/schema.ts` is portable; you only need to swap the
  client in `src/lib/db/index.ts` and adjust `drizzle.config.ts`.

## Roadmap

The architecture deliberately leaves room for the integrations you'll add next:

- [ ] **Google Calendar sync** — surface `due_date` on the calendar and push
      task completions back. Hooks: a future `src/lib/integrations/google/`
      module + `googleEventId` column.
- [ ] **Recurring tasks** — repeat rules driven by RRULE strings.
- [ ] **Tags / projects** — many-to-many via a `tags` table.
- [ ] **Multi-user** — add an `auth` provider (Auth.js) and scope tasks by
      `userId`.
- [ ] **Keyboard shortcuts** — `n` to add, `j/k` to navigate, `e` to edit.
- [ ] **PWA / offline** — service worker + IndexedDB cache.

## Accessibility & UX notes

- All interactive surfaces are keyboard-reachable; menus and dialogs use
  Radix primitives that handle focus management for you.
- Hit-targets stay ≥ 36×36 px on touch devices.
- The task action menu is always visible on mobile (it only hides-on-hover at
  `sm` breakpoints and above) so touch users can reach it.
- Color is never the only signal: priority and status both pair an icon with
  the color.
